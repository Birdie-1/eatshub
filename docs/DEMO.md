# สคริปต์เดโม eatsHub (ประมาณ 5 นาที)

> เว็บจำลองสำหรับนำเสนอ ข้อมูลตัวอย่าง ไม่มีการเรียกเก็บเงินจริง ไม่มี Google OAuth จริง
> รัน `npm install` และ `npm run dev` จากโฟลเดอร์ที่มี `package.json` แล้วเปิด Local URL ที่แสดง
> หรือเปิดเวอร์ชัน production ที่ https://eatshub-red.vercel.app

## 0:00–0:30 — ทางเข้าและเข้าสู่ระบบ (#8)

1. เปิด `/` อธิบายทางเข้าแอปลูกค้าและระบบหลังบ้าน บนจอใหญ่สองการ์ดอยู่คู่กัน บนมือถือวางซ้อน
2. เลือก **เปิดแอปลูกค้า** กดเข้าสู่ระบบด้วยข้อมูลสาธิตที่กรอกไว้แล้ว หรือปุ่ม Google จำลอง
3. ถ้ามี session อยู่แล้ว Landing จะเข้าแอปได้ทันที
4. ชี้ให้เห็นว่า desktop ใช้กรอบโทรศัพท์ ส่วนมือถือเต็มจอ

## 0:30–1:40 — เลือกอาหารและตะกร้า (#3–#6)

1. ค้นหา **สุกี้** → **ราชาอาหาร** → **สุกี้รวมมิตร**
2. เลือกสุกี้น้ำ เปิดส่วนเสริม เลือกกุ้ง (+15) และลูกชิ้นปลา (+10) → ยืนยัน → เพิ่ม 127 บาท
3. เพิ่มบะหมี่หมูแดง 88 บาท → เปิดตะกร้า ค่าอาหาร 215.00 บาท
4. พิมพ์หมายเหตุถึงร้าน/ไรเดอร์ แล้วใช้คูปอง **EATSHUB20**
5. อธิบายยอดจากกติกากลาง: 215 + 10 − 32.25 − 20 = **172.75 บาท**, ได้ **9 คะแนน**
6. แถบตะกร้าลอยแสดงยอดสุทธิชุดเดียวกับหน้าตะกร้าและ Checkout
7. หากต้องการโชว์การเปลี่ยนร้าน ให้เพิ่มเมนูจากแม่แดง: ระบบถามก่อนล้างตะกร้า กด **ยกเลิก** เพื่อรักษาตะกร้าเดิม

## 1:40–2:30 — Checkout และการชำระเงิน (#11)

1. เปิด Checkout ชี้รายการอาหาร หมายเหตุ ที่อยู่บ้าน/ออฟฟิศ และวิธีจ่าย 3 แบบ
2. เดโมหลักเลือก **เก็บเงินปลายทาง** → ชำระเงิน → หน้าสั่งอาหารสำเร็จ พร้อมเลขออเดอร์และยอด 172.75 บาท
3. รอบเสริมใช้ PromptPay: QR มีคำว่า **ตัวอย่าง** และไม่ใช่ QR รับเงินจริง มีอายุ 10 นาที กด **ฉันชำระเงินแล้ว** เพื่อจำลองการตรวจสอบ
4. รอบเสริมใช้ PayPal: แสดงยอดและปุ่มยืนยัน ไม่มีช่องกรอกรหัสผ่าน/ข้อมูลการเงิน
5. ปุ่มยกเลิกหน้าจ่ายเงินกลับ Checkout โดยตะกร้ายังอยู่
6. เมื่อสำเร็จ ตะกร้าว่าง ออเดอร์และยอดถูกบันทึกเป็น snapshot เลขออเดอร์ไล่ต่อจากตัวอย่าง ไม่สุ่ม

## 2:30–3:30 — ติดตามและประวัติ (#12)

1. กด **ติดตามออเดอร์** สถานะเปลี่ยนทุก **8 วินาที** จบ 5 ขั้นในประมาณ 32 วินาที
2. กด **ข้ามไปขั้นถัดไป ›** เมื่อต้องการเร่งการนำเสนอ
3. ตั้งแต่ขั้น 2 แสดงสมชาย EA00001 เบอร์ 010 971 6354 และทะเบียนตรงกับหลังบ้าน
4. การ์ดไรเดอร์แสดงชื่อ รหัส ทะเบียน และเบอร์โทร (ไม่มีปุ่มโทร/แชท เพราะอยู่นอกขอบเขต)
5. Refresh กลางทาง สถานะคำนวณจากเวลาที่สั่งกับ offset จึงไม่เริ่มใหม่
6. เมื่อ COD ส่งถึงแล้ว สถานะการจ่ายเปลี่ยนเป็น **ชำระแล้ว** และมีปุ่มให้คะแนน
7. เปิดแท็บออเดอร์: ตัวอย่าง 4 รายการ + ออเดอร์ที่เพิ่งสั่งเรียงใหม่สุดก่อน
8. ออกจากระบบผ่านบัญชี ตะกร้าถูกล้าง แต่ประวัติยังอยู่เมื่อเข้าใหม่

## 3:30–4:40 — ระบบหลังบ้าน (#9–#10)

1. กลับ Landing → เปิดระบบหลังบ้าน → username `admin` และรหัสผ่านสาธิต → เข้าสู่ระบบ
2. เข้าสู่แดชบอร์ด `/admin`: ชี้ KPI 177,321 บาท / 946 ออเดอร์ / 45 เมนู / 17 ไรเดอร์ ดูกราฟรายเดือนและ Top 5 จากนั้นดูออเดอร์ที่เพิ่งสั่งในส่วนออเดอร์ล่าสุด แล้วกด **จัดการไรเดอร์**
3. Sidebar มีเฉพาะหน้าที่ทำแล้ว (แดชบอร์ด · จัดการไรเดอร์ · ออกจากระบบ) บนมือถือเปิด drawer ด้วย ☰
4. ไรเดอร์ 17 คน: ค้นหา **สมชาย**, **EA00005**, **9กก9324** หรือ **0109716354**
5. ล้างค้นหา กรอง Delivery แล้วเรียง/แบ่งหน้า (หน้า 2 มี 11–17)
6. เปลี่ยน Active → Block ต้องกรอกเหตุผล → ยืนยัน เห็น badge ผู้แก้ไข Admin และเวลาปัจจุบัน
7. เปลี่ยนกลับ Active ได้ทันที รีเฟรชคืนข้อมูลตั้งต้น (การสาธิตไม่บันทึกถาวร)
8. Logout กลับ Landing และเข้าหลังบ้านตรง ๆ ไม่ได้จนกว่า login ใหม่

## 4:40–5:00 — สรุปการนำเสนอ

- เดิน flow สั่งอาหารได้ครบ และยอดตรงกันทุกหน้า
